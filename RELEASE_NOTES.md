# v0.2.0 — release notes (2026-11-09)

Status: **released**. Phase 2 of the chatgpt-proxy provider for the
EasyCLI/CLIProxyAPI v8 host — full feature parity with the MIT reference,
on top of the v0.1.0 credential lifecycle, model catalog, quota cards and
the `openai` / `openai-image` executors.

## Compatibility

- Deploy is unchanged from v0.1.0: a copy of the glibc `linux/amd64` `.so`
  into the host's plugin directory plus the
  `plugins.configs.easycliproxyapi-chatgpt-provider` block in the live
  `config.yaml` (see README Deploy); a restart picks it up. The three new
  search config keys (`search-upstream-model`, `search-timeout-secs`,
  `search-poll-interval-secs`) are optional — they default to the reference
  constants.
- Identity and contracts are pinned by tests: plugin id
  `easycliproxyapi-chatgpt-provider`, version `0.2.0`, provider key /
  model prefix / auth-file type `chatgpt-proxy`, the registry.json store
  entry, and the README contract matrices.
- The registration envelope grows additively: the executor formats gain
  `openai-response` and `claude`, the capabilities gain `management_api`,
  and the auth surface gains the synchronous `auth.login.password` method
  (it rides the existing `auth_provider` capability).

## What landed (each feature reviewed against the reference oracle)

- **Responses API format (`openai-response`)** — commit `8088a7d`.
  `/v1/responses` in/out over the shared conversation pipeline; the
  `image_generation` tool routes through the image pipelines and emits
  `image_generation_call` items; function tools reuse the XML emulation.
- **Anthropic Messages format (`claude`)** — commit `0474613`.
  `/v1/messages` in/out with tool_use/tool_result block flattening, the
  Claude Code rule-swap, the `message` envelope + Anthropic SSE sequence,
  and the host-rendered Anthropic error envelope (verified against the host
  SDK's Claude handler).
- **Web search** — commit `463f79f`. `web_search` tools / search model
  prefixes route through the upstream search flow (prepare +
  `force_use_search` + conversation poll) and return the cited answer
  (`Sources:` block + `url_citation` annotations) in every text format.
- **Password re-login** — commit `ce9891c`. Synchronous
  `auth.login.password`: auth-flow sentinel (FNV-1a-32 PoW, vectors
  differentially pinned to the reference Python) + PKCE S256 +
  `password/verify` + `oauth/token`; the recovered credential stores exactly
  like a browser login (`source_type:"password"`).
- **CPA / sub2api account imports** — commit `09117d7`. The new
  `management_api` capability + five exact-path host Management API routes
  (`chatgpt-proxy/import/cpa-file`, `chatgpt-proxy/import/cpa-remote[/files]`,
  `chatgpt-proxy/import/sub2api[/accounts]`) that write
  `type:"chatgpt-proxy"` records via `host.auth.save`.
- **Drawing workbench** — commit `7354044`. A data-free, dependency-free
  HTML/JS resource page under `/v0/resource/plugins/<plugin-id>/` plus
  `chatgpt-proxy/workbench/generate|edit|models` management routes driving
  the existing image pipeline (client-side history, synchronous turns).

## Offline-verified surface

Everything above is exercised by the default `go test ./...` suite — no
network, no credentials, no host binary — and by CI, which builds the glibc
`linux/amd64` artifact and then runs the same suite, so the load smoke
`dlopen()`s the real `.so`. New pins this release:

- Responses input mapping, the `response.completed` envelope, the SSE event
  sequence (close-once, no `[DONE]`), the image tool → image pipeline, and
  the zero-content 502.
- Claude message flatten / merge_system / rule-swap, the `message`
  envelope, the Anthropic SSE sequence, the tool_use round-trip, and the
  error-envelope decision (host-rendered — pinned against the SDK).
- Search detection (the exact oracle condition incl. the mixed-tools
  control), the prepare/SSE/poll flow (finished-status + stable-text stops,
  the swallow set, the 401 never-swallowed), source extraction + the
  `SearchCitedAnswer` rendering + annotation ranges, and the per-format
  routing in all three text formats.
- The FNV-1a-32 PoW differential (literals generated by running the
  reference Python), the password-verify/token-exchange request shapes,
  `continue_url` parsing, the OTP-refusal path, PKCE, storage parity, and
  the byte-scan secret-hygiene assertions (the password appears only in the
  verify body).
- Management register/handle routing (200/404/405, full-vs-relative paths),
  the CPA + sub2api import flows against scripted transports (including the
  reference's envelope-unwrap and paging), credential storage parity +
  `auth.parse` round-trip, dedupe, and the canary secret-hygiene scan.
- The workbench routes driving the reused image pipeline (no fork), the
  credential acquisition for the management context, the data-free shell
  (byte-pinned under a canary config), and the n 1..4 validation.

## Live verification — operator-gated

The v0.1.0 live-verification items remain operator-gated (TLS fingerprint
spike, live executor smoke, SCPM gateway integration) — see
`PROVENANCE.md` for the verdict ledger.

After the v0.2.0 deploy, `PROVENANCE.md` records a live serving pass
(2026-11-09/10): one `/v1/responses` turn plus its streaming SSE sequence,
one `/v1/messages` turn plus its streaming SSE sequence, a Responses
`image_generation` tool round (an `image_generation_call` item from the
live image pipeline), a web-search turn returning cited sources, the
workbench resource page + models + generate + edit rounds (all against the
live ChatGPT Plus credential, through the public gateway port), and the
import routes proven registered + dispatching (typed validation /
remote-failure responses, no credential written). The pass includes the
four Phase-2 review minors (`3aa37d2`), re-deployed and re-verified before
the tag moved.

Still operator-gated (they need credentials this repo must not hold):

- one `auth.login.password` recovery on a sacrificial account (OTP-enabled
  accounts must refuse typed, not hang);
- a real CPA or sub2api credential import through the EasyCLI panel,
  confirming the saved record serves text turns.

## Remaining gaps (post-Phase-2)

- **Executor extensions** (the old P2-7): parallel `n>1` generation,
  per-credential proxy fields, a `chat_completion_cache` equivalent,
  image `base_url` / retention settings.
- **Import follow-ups**: pool/server CRUD + the persisted async import-job
  record (F5 takes the source config inline per call), the sub2api
  `api_key` auth alternative and its groups listing, and a dedicated 2FA
  error class (non-email-OTP 2FA pages land in retryable `no_auth_code`,
  reference-faithful).
- **Workbench follow-ups**: server-side persistent history (F6 keeps it
  client-side, like the reference).
- Shipped in v0.2.1: the registration `ConfigFields` (the panel's
  plugin-settings UI renders every tunable key) and the
  `POST chatgpt-proxy/login/password` management route (the panel surface
  for the `auth.login.password` recovery core).

Also unchanged from v0.1.0: exact token counts are not available upstream
(usage is a documented `bytes / 4` estimate).
